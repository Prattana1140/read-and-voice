# ThaiD OAuth Setup

Read and Voice currently supports ThaiD login through the backend OAuth flow.

ThaiD is DOPA-Digital ID from the Department of Provincial Administration. The client credentials and OAuth/OIDC endpoint URLs are not generated by this project. They must be issued during DOPA/ThaiD onboarding for your relying party system.

## Callback URLs

Local development:

```text
http://localhost:3000/api/auth/oauth/thaid/callback
```

Production:

```text
https://your-api-domain.com/api/auth/oauth/thaid/callback
```

Use the exact callback URL when registering the app with ThaiD/DOPA.

## Backend Environment

Add these values to `backend/.env` after ThaiD/DOPA provides them:

```env
FRONTEND_URL=http://localhost:5173
API_PUBLIC_URL=http://localhost:3000

THAID_CLIENT_ID=your-thaid-client-id
THAID_CLIENT_SECRET=your-thaid-client-secret
THAID_AUTH_URL=authorization-endpoint-from-thaid
THAID_TOKEN_URL=token-endpoint-from-thaid
THAID_PROFILE_URL=profile-or-userinfo-endpoint-from-thaid
THAID_SCOPE=openid profile email
```

For production, `API_PUBLIC_URL` must be the public backend URL and `FRONTEND_URL` must be the public frontend URL.

## Check Setup

Restart the backend after changing `.env`, then open:

```text
http://localhost:3000/api/auth/oauth/status
```

Expected result:

```json
{
  "provider": "thaid",
  "configured": true,
  "callbackUrl": "http://localhost:3000/api/auth/oauth/thaid/callback"
}
```

## Login Flow

1. User opens `/login`.
2. User clicks ThaiD login.
3. Backend redirects to `THAID_AUTH_URL`.
4. ThaiD redirects back to `/api/auth/oauth/thaid/callback`.
5. Backend exchanges the code at `THAID_TOKEN_URL`.
6. Backend loads the user profile from `THAID_PROFILE_URL`.
7. Backend creates or finds the local user account and redirects to `/oauth/callback`.
